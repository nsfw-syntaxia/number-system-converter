1 System requirements

Functional requirements

  • Accept at least three input numbers; the user sets the exact count (3 to 8 in this build).
  • For each input the user selects a base: binary (2), octal (8), decimal (10), or hexadecimal (16).
  • A value may include a fractional part after a point — e.g. 1010.12, 3.510, A.816.
  • Each value is validated against the digit set of its selected base before it is used.
  • Every valid input is converted into all four bases and displayed individually.
  • Simple chain mode — the user selects one operation (+, −, ×, ÷) and it is applied to the inputs left to right: ((v1 op v2) op v3) …
  • Expression mode — the user may instead type a free-form expression that combines the inputs (labelled a, b, c, … in input order) with different operators and parentheses, e.g. (a + b − c) × d.
  • Expressions follow standard operator precedence (× and ÷ run before + and −) and left-to-right associativity for operators that share a precedence level; parentheses override both.
  • Inputs of different bases are converted to a common representation (decimal) before any operation runs.
  • Output shows the expression using the original input values, the same expression with each variable substituted by its decimal value, and the final result in binary, octal, decimal, and hexadecimal.
  • Complements — for every whole-number input, show its 1’s complement (every bit flipped) and 2’s complement (1’s complement + 1) in binary, octal, decimal, and hexadecimal.
  • Complements are taken in a fixed-width word chosen by the user: Auto (smallest multiple of 4 bits, at least 8, that holds every value and a sign bit), or 8, 16, or 32 bits.
  • Subtraction using complements — v1 − v2 − v3 … is worked out left to right by adding the complement of each subtrahend, once with the 1’s complement method (a carry out of the top bit is added back — the end-around carry) and once with the 2’s complement method (the carry out is dropped). No carry means the result is negative and is stored in complement form; the sign bit shows it.
  • Every complement subtraction is checked against plain subtraction, so a word that is too small is reported instead of giving a wrong answer.
  • BCD (8421) addition — v1 + v2 + v3 … is worked out digit by digit in BCD. Where a digit sum is greater than 9, 0110 (6) is added to correct it and a carry goes to the next digit.
  • BCD subtraction — v1 − v2 − v3 … is worked out by adding the 9’s complement (every digit 9 − d; a carry out of the top digit is added back) and, separately, the 10’s complement (9’s complement + 1; the carry is dropped). A leading digit of 9 marks a negative result.
  • The BCD word is chosen in decimal digits: Auto, or 3, 4, 6, or 8. The leading digit is the sign digit, so every running value must be below 10D−1. BCD works on whole, non-negative numbers; fractional or negative inputs are reported, not rounded.
  • Invalid input, missing input, division by zero, and malformed expressions are all caught and reported without crashing — see Arithmetic error handling below.

Non-functional requirements

  • Single page, no installation, runs in any modern browser.
  • Values are stored as exact fractions (BigInt numerator / denominator), so conversion and arithmetic never lose precision. Repeating expansions are shown truncated.
  • Conversions, the result, and the complement and BCD workings update immediately as inputs or the word size change.
  • Steps 2, 3, 4, and 5 stay locked until every input number is valid, so the flow is followed in order.
  • The Documentation tab can be exported to a neatly paginated PDF report directly from the browser (cover page, one section per page, tables and figures never split across pages).

Arithmetic error handling

Every error is caught before it reaches the result and shown inline in a highlighted panel instead of a stack trace or a blank screen. The calculation simply does not run until the problem is fixed.

2 Algorithm / pseudocode

// Number System Converter and Arithmetic Calculator

BEGIN
  READ n                          // how many numbers, n >= 3

  FOR i FROM 1 TO n DO
      READ base[i]                 // 2, 8, 10 or 16
      READ value[i]                // text entered by the user

      IF value[i] is not valid for base[i] THEN
          PRINT "Invalid input for base " + base[i]
          ask again for value[i]
      ENDIF

      dec[i] ← TO_DECIMAL(value[i], base[i])
      PRINT value[i] " in BIN / OCT / DEC / HEX ="
            TO_BASE(dec[i], 2), TO_BASE(dec[i], 8),
            TO_BASE(dec[i], 10), TO_BASE(dec[i], 16)
  ENDFOR

  READ op                         // + , - , * , /

  result ← dec[1]
  FOR k FROM 2 TO n DO
      IF op = "/" AND dec[k] = 0 THEN
          PRINT "Error: division by zero"
          STOP
      ENDIF
      result ← APPLY(op, result, dec[k])
  ENDFOR

  PRINT expression using original value[1..n] and op
  PRINT "= " TO_BASE(result, 2), TO_BASE(result, 8),
             TO_BASE(result, 10), TO_BASE(result, 16)
END

FUNCTION TO_DECIMAL(text, base)
  split text into intText and fracText on "."
  total ← 0
  FOR each digit d in intText, left to right DO
      total ← total * base + digitValue(d)
  place ← 1
  FOR each digit d in fracText, left to right DO
      place ← place / base
      total ← total + digitValue(d) * place
  RETURN total                // kept as an exact fraction

FUNCTION TO_BASE(number, base)
  sign ← ""
  IF number < 0 THEN sign ← "-" ; number ← -number
  intPart ← floor(number) ; frac ← number - intPart

  digits ← ""
  IF intPart = 0 THEN digits ← "0"
  WHILE intPart > 0 DO
      digits ← symbol(intPart mod base) + digits
      intPart ← intPart div base

  IF frac > 0 THEN
      digits ← digits + "."
      REPEAT up to MAX_FRAC_DIGITS times, while frac > 0 DO
          frac ← frac * base
          digits ← digits + symbol(floor(frac))
          frac ← frac - floor(frac)

  RETURN sign + digits

Complements and subtraction by complement run after the conversions, on the same decimal values. The word size w is chosen first, then every value is stored as a w-bit pattern:

// w = word size in bits.  Patterns are integers 0 .. 2^w - 1.
// system = 1 (1's complement) or 2 (2's complement)

FUNCTION CHOOSE_WORD(values, choice)
  need ← 1 + longest bit length among every whole value and every running result
  IF choice = AUTO THEN RETURN max(8, need rounded up to a multiple of 4)
  IF need > choice THEN THROW "word too small"
  RETURN choice

FUNCTION ONES(p, w)    RETURN p XOR (2^w - 1)             // flip every bit
FUNCTION TWOS(p, w)    RETURN (ONES(p, w) + 1) MOD 2^w    // flip, then add 1

FUNCTION ENCODE(v, w, system)                 // how a value is stored
  IF v >= 0 THEN RETURN v
  IF system = 1 THEN RETURN 2^w - 1 - |v|         // 1's complement of |v|
  RETURN 2^w - |v|                          // 2's complement of |v|

FUNCTION SUBTRACT_STEP(A, B, w, system)       // A - B by adding a complement
  negB ← (system = 1) ? ONES(B, w) : TWOS(B, w)
  sum  ← A + negB
  carry ← sum >= 2^w ; sum ← sum MOD 2^w
  IF carry AND system = 1 THEN sum ← sum + 1     // end-around carry
                                              // system 2: the carry is dropped
  IF top bit of sum = 0 THEN value ← sum          // positive
  ELSE value ← -(complement of sum)             // negative
  RETURN sum, value

BEGIN COMPLEMENTS
  w ← CHOOSE_WORD(dec[1..n], choice)
  FOR i FROM 1 TO n DO
      p ← ENCODE(dec[i], w, 2)
      PRINT ONES(p, w) and TWOS(p, w) in BIN / OCT / DEC / HEX

  FOR system IN (1, 2) DO
      acc ← ENCODE(dec[1], w, system)
      FOR k FROM 2 TO n DO
          acc, value ← SUBTRACT_STEP(acc, ENCODE(dec[k], w, system), w, system)
          IF value ≠ (dec[1] - ... - dec[k]) THEN THROW "word overflowed"
      PRINT acc in BIN / OCT / DEC / HEX, and value
END

Expression mode replaces the single READ op / APPLY loop above with a small recursive-descent parser so the user can mix operators and parentheses freely. Grammar, lowest to highest precedence:

// expr   := term (("+" | "-") term)*        -- + and - , left associative
// term   := factor (("*" | "/") factor)*    -- * and / , left associative, binds tighter
// factor := ("+" | "-") factor | primary     -- unary sign
// primary:= NUMBER | VARIABLE | "(" expr ")"

FUNCTION TOKENIZE(text)
  tokens ← empty list
  FOR each character c in text, left to right DO
      IF c is whitespace THEN skip
      ELSE IF c is "(" or ")" THEN tokens.push(c)
      ELSE IF c is "+" "-" "*" "/" THEN tokens.push(OP, c)
      ELSE IF c is a digit or "." THEN
          consume following digits/"." → text2
          tokens.push(NUMBER, text2)
      ELSE IF c is a letter THEN tokens.push(VARIABLE, lowercase(c))
      ELSE THROW "Unexpected character " + c
  RETURN tokens

FUNCTION PARSE_EXPR(tokens)
  node ← PARSE_TERM(tokens)
  WHILE next token is "+" or "-" DO
      op ← consume() ; right ← PARSE_TERM(tokens)
      node ← { BIN, op, node, right }
  RETURN node

FUNCTION PARSE_TERM(tokens)
  node ← PARSE_FACTOR(tokens)
  WHILE next token is "*" or "/" DO
      op ← consume() ; right ← PARSE_FACTOR(tokens)
      node ← { BIN, op, node, right }
  RETURN node

FUNCTION PARSE_FACTOR(tokens)
  IF next token is "+" or "-" THEN
      op ← consume()
      RETURN { UNARY, op, PARSE_FACTOR(tokens) }
  RETURN PARSE_PRIMARY(tokens)

FUNCTION PARSE_PRIMARY(tokens)
  IF next token is "(" THEN
      consume "(" ; node ← PARSE_EXPR(tokens)
      IF next token is not ")" THEN THROW "Missing closing )"
      consume ")" ; RETURN node
  ELSE IF next token is NUMBER or VARIABLE THEN RETURN consume()
  ELSE THROW "Expected a number, variable, or ("
  // tokens left over after PARSE_EXPR returns -> "unexpected token" / unmatched ")"

FUNCTION EVALUATE(node, values)        // values[letter] = decimal value of that input
  SWITCH node.type
      NUMBER:   RETURN TO_DECIMAL(node.text, 10)
      VARIABLE: IF values[node.name] is undefined THEN THROW "Unknown variable " + node.name
                RETURN values[node.name]
      UNARY:    v ← EVALUATE(node.expr, values)
                RETURN (node.op = "-") ? -v : v
      BIN:      l ← EVALUATE(node.left, values) ; r ← EVALUATE(node.right, values)
                IF node.op = "/" AND r = 0 THEN THROW "Division by zero"
                RETURN APPLY(node.op, l, r)

BCD (8421): every decimal digit is a 4-bit group. D is the word size in digits; the leading digit is the sign digit (0 = positive, 9 = negative).

// digits are numbered 1 (least significant) .. D (leading, sign digit)

FUNCTION BCD_ADD(a, b, D)              // a[i], b[i] = the 4-bit digits
  carry ← 0
  FOR i FROM 1 TO D DO
      raw ← a[i] + b[i] + carry             // binary addition of two digits
      IF raw > 9 THEN                   // +0110 correction, carry 1
          sum[i] ← raw - 10 ; carry ← 1
      ELSE sum[i] ← raw ; carry ← 0
  RETURN sum, carry

FUNCTION COMPLEMENT9(b, D)            // every digit 9 - d  (= 10^D - 1 - b)
  RETURN 9 - b[i] for i = 1 .. D

FUNCTION COMPLEMENT10(b, D)           // 9's complement + 1
  RETURN BCD_ADD(COMPLEMENT9(b, D), 1, D)

FUNCTION SUB_STEP(A, B, D, method)    // A - B by adding a complement
  negB ← (method = 9) ? COMPLEMENT9(B, D) : COMPLEMENT10(B, D)
  sum, carry ← BCD_ADD(A, negB, D)
  IF method = 9 AND carry = 1 THEN sum ← BCD_ADD(sum, 1, D)   // end-around carry
                                              // method 10: the carry is dropped
  RETURN sum

FUNCTION DECODE(r, D, method)         // leading digit 9 = negative
  IF leading digit of r ≠ 9 THEN RETURN r
  RETURN -(method = 9 ? (10^D - 1 - r) : (10^D - r))

BEGIN BCD_ADDITION
  w ← CHOOSE_DIGITS(dec[1..n], choice)
  acc ← dec[1]
  FOR k FROM 2 TO n DO
      acc, carry ← BCD_ADD(acc, dec[k], w)
      IF carry = 1 THEN THROW "word overflowed"
  PRINT acc in BCD, and its decimal value
END

BEGIN BCD_SUBTRACTION
  w ← CHOOSE_DIGITS(dec[1..n], choice)
  FOR method IN (9, 10) DO
      acc ← dec[1]
      FOR k FROM 2 TO n DO
          acc ← SUB_STEP(acc, dec[k], w, method)
          IF DECODE(acc, w, method) ≠ (dec[1] - ... - dec[k]) THEN THROW "word overflowed"
      PRINT acc in BCD, and DECODE(acc, w, method)
END

4 Program implementation

No build step or framework — eight plain <script> files, loaded in dependency order, with the calculation logic kept free of DOM code so it can be read (or unit-tested) on its own.

Modules

  • js/rational.js — exact rational arithmetic on BigInt fractions: rat(), ratAdd, ratSub, ratMul, ratDiv (throws on ÷0), ratNeg.
  • js/converter.js — BASES metadata, parseValue() (text + base → rational, validates digits), toBaseParts() / toBase() (rational → text in a base).
  • js/arithmetic.js — OP_SYMBOL / OP_FN maps and applyOperation() for Simple chain mode: folds an operator across values left to right.
  • js/expression.js — tokenizeFormula(), parseFormulaTokens() (the recursive-descent parser that implements precedence and left associativity), evaluateFormulaAst(), and renderFormulaHTML() for Expression mode.
  • js/complement.js — complementWidth() (word size), onesComplement() / twosComplement() / complementsOf(), encodeValue() / decodeValue() (how a negative number is stored and read back in each system), subtractStep() (one subtraction by adding a complement), and chainSubtract() / complementSubtraction() (v1 − v2 − … by both methods, every step checked against plain subtraction).
  • js/bcd.js — bcdWidth() (digit count), bcdString() (8421 groups), complement9() / complement10(), bcdAdd() (digit by digit with the +6 correction), bcdSubtractStep() (one subtraction by the 9’s or 10’s complement), and bcdChainAdd() / bcdChainSubtract() (left to right, every step checked against plain arithmetic).
  • js/testcases.js — TEST_CASES, the activity's test matrix: base combinations, fractional values, negative results, expression formulas, and forced error cases; plus COMPLEMENT_VALUES and COMPLEMENT_CASES for the complement tests, plus BCD_VALUES and BCD_CASES for the BCD tests.
  • js/app.js — UI layer: builds the input rows, wires the mode toggle, validates and renders Steps 1–5, the step-unlock animation, the Documentation tab (test tables, sample output), and the Export PDF button.

Calculator interface

The running program, Steps 1–5, for each operation mode — screenshots, not a mockup (regenerate them with tools/capture-screenshots.mjs).

Step 4 — complements and subtraction by complement

Same inputs (111102 − 910 − A16) in the automatic 8-bit word. Every step shows B, the complement of B, the sum, what happens to the carry, and the result.

A negative result (510 − 10102 − 016 = -5): there is no carry, the sign bit is 1, and the magnitude is recovered by complementing the sum.

Step 5 — BCD addition and subtraction

The same kind of inputs, shown in 8421 BCD, then the sum and both complement subtractions. Example: 1210 − 3010 − 116 = -19.
